Security questions from the task:
- **(a) What a share link exposes.** A share link returns the share name, its expiry, and for each deck its name, tags, banner card, format and color identity, plus the full `.cod` snapshot through `Command_DeckShareDownload` (serversocketinterface.cpp:1302-1355). It doesn't expose the owner's name, folder path or other decks. Webatrice leaks two things desktop doesn't: the token in the query string (web-host logs and history; major above) and the token in Redux action payloads, visible in devtools. It keeps the token in `sessionStorage` until login and clears it on read, which is fine. The token isn't written to `localStorage`, and `lastRoute` keeps only the pathname.
- **(b) Revoke.** Revoke works end to end. `deckShareRemove(shareId)` sends `Command_DeckShareRemove`. On success the store filters `deckSharesMine`; on failure the dialog shows an error with the code. Servatrice cascades the delete, so the link then gives NameNotFound, shown as "not found or expired", and the e2e spec covers it. Copies already imported survive, as on desktop. Unpublish matches desktop: it flips the node's own bit, so an inherited deck stays public.
- **(c) `?share=` route.** There is no open redirect or injection:
  - `captureDeckShareLink` copies only `share`, `hostname` and `port` through `URLSearchParams`, which re-encodes them.
  - The redirect goes to the fixed in-app pathname `/decks/shared`. Nothing sets `window.location` or calls `window.open`, and the link's host or path is never followed.
  - `hostname` is rendered as React text, so it is escaped.
  - The token only goes into protobuf fields.
  - When the visitor isn't logged in, the link waits for login (the `AuthGuard` checks `LOGGED_IN`).
  - The remaining risk is the token going to the **wrong server** (the fail-open and port findings above), not navigation.

Checked and fine:
- Layering: UI → `request.session.*`, with only `SessionResponseImpl` dispatching.
- `i18n-default.json` equals a fresh merge of the `*.i18n.json` files.
- The reducer uses `cloneWith`.
- The sockatrice and datatrice changesets are present and minor, and `deckSharingFailed` is optional.

**Verdict 23d: ready after fixes.** The two privacy majors (token in the query string, fail-open server check) must be fixed before upstream.
