## Notes (verified, not findings)
- **Join-by-id fix is real and correct.** Old `onActivateGame: () => beginJoin()` read `selectedGame` derived
  from the selector, which is stale on the first double-click/Enter of an unselected row (store updated, component
  not yet re-rendered). New `joinById(gameId, …)` uses the event's id directly; `beginJoin` likewise switched to
  `selectedGameId`. Good catch by the author.
- **`useGridRows` change is safe for the other callers.** Replays (tree), card-art-rules, reports and user-games
  all have their rows always mounted, so the `focusRequest` effect focuses immediately — same behaviour as the old
  `focusKey` state. The new ref-callback focus-on-mount only fires while a focus request is pending, which for those
  callers is cleared synchronously by the effect, so it never steals focus on an unrelated remount. Their specs pass.
- **Dead-code deletion is clean.** No live importer, i18n key, css or e2e reference to GameSelector/OpenGames/
  SayMessage remains (only comments and the retained, still-used `useOpenGames` hook). The PR also correctly notes
  `Messages.tsx` is likewise dead but out of scope.
- **i18n / changeset scope.** New strings for TopBar tabs, KnownHosts and ShortcutsRow are in co-located
  `*.i18n.json` and regenerated into `i18n-default.json`; only `@cockatrice/webatrice` changed, so a single
  changeset is correct. GamesList's own column/empty-state literals stay untranslated — pre-existing, deferred to
  i18n PR D.
- **VirtualRows P17 passthrough** matches react-window v2's runtime (`aria-posinset`/`aria-setsize`/`role=listitem`
  confirmed in the installed build); gated off when the caller sets its own role, so the grid keeps its rows.

## Verdict
**ready after fixes** — address or explicitly accept the KnownHosts listbox (major); the rest are minor/defer.
Functionally and for the P1 blocker it is solid: the keyboard-only journey passes on all three engines.
