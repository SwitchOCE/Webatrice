| major | `packages/webatrice/src/features/game/hooks/usePlaymatSync.ts:36-41` (mounted from `features/game/Game.tsx:72`) | All sync state (`deckPlaymat`, `lastSent`, `lastResolved`, `rotation`) lives in refs of the `Game` route component. `Game` unmounts whenever the user leaves `/game/:id` (`AppShellRoutes.tsx:31`), and Settings is a separate route (`:37`), so the documented "change settings → re-resolve" flow always goes through a remount. After a remount, `lastSent === undefined` makes the hook treat the server's echo of its **own** previous `SetPlaymat` as the deck's playmat (`:60`). Repro: deck with playmat D, mode Override, collection [A] → A is sent. Go to Settings, switch to "Deck only", come back: `deckPlaymat = A`, DECK_ONLY resolves A, nothing is sent, and the table keeps A instead of D. The same remount resets the round-robin cursor to 0 and forgets `lastResolved`, so random can repeat. The spec only re-renders the hook in place and never unmounts it, so it can't catch this.
