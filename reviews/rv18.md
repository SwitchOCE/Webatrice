| severity | file:line | finding | concrete fix |

| major | `.changeset/datatrice-game-listeners-split.md:2` | The PR adds public API: `games.Selectors.getArrowsTouchingCard` and `export type ArrowRef` (`games/index.ts:16`), and the changeset text itself announces the selector. A `patch` here publishes new API under a patch version. | Either bump to `'@cockatrice/datatrice': minor`, or (better, see the next row) keep the scan internal, drop `ArrowRef` from `index.ts`, and leave the changeset at `patch` with the API sentence removed. |
| major | `cardMove.ts:75`, `cardMove.spec.ts:116-131`, characterization stream | The same-zone reorder set has four zones (HAND, STACK, GRAVE, EXILE). Only HAND is pinned anywhere. The PR claims every `cardMoved` placement is table-tested and pinned. | Add `same-zone` rows for `stack`, `grave` and `exile` to the `planMovePlacement` table. Its only caller is the `cardMoved` effect. | Make it a non-exported state scan (a plain function in `game.selectors.ts` or `cardMove.ts`, still specced). **Design notes (no action needed):**
- The split follows real seams: zones, cards, counters, arrows, players, phases. Each module has one
  `register<Domain>Listeners`, and there is no grab-bag utils.
- The `cardMove.ts` planners are pure apart from `planOptimisticReconcile`'s documented post-dispatch input.
- The deviation from aud2's `{card,move,reveal,turn,player}` naming is explained.
- The 307-line zones module is justified.
- The doc link fixes are correct.

**Verdict: ready after fixes.** The refactor is behaviour-preserving as far as I can verify by reading and by
mutation. It needs the changeset/API decision and the STACK/EXILE same-zone coverage before upstream.
