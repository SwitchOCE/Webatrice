## G1 commit (`57a3449`)

- Shift+Tab = Next phase with action: correct (`defaults.ts`, pinned by `ShortcutProvider.spec` through the real
  listener). Previous phase is unbound, as on desktop.
- Inside dialogs, menus and controls, Tab / Shift+Tab are not eaten. `keepsTabNavigation` returns before
  `preventDefault` for `[role=dialog|alertdialog|menu]`, `[aria-modal=true]` and form controls / buttons /
  links / button-like roles. Specs cover a button, a menu and a non-modal dialog, and assert the event is not
  prevented.
- Modal guard: while an `aria-modal="true"` element is mounted, `activeRoute = null`, so only GLOBAL
  registrations fire. No GLOBAL default is bound to Escape (`defaults.ts:47`; Escape is only
  `game.closeRecentView`, GAME scope), so Escape reaches the modal. MUI 9 `Dialog` sets `aria-modal` by default
  (`ariaModal = true`), and `DialogShell` and the hand-rolled dialogs set it explicitly, so the guard covers
  every modal in the app.
- **But see major M1:** on the board itself the guard also swallows the desktop binding whenever an own card has
  focus.

## e2e claim "75/90 (+3 fixed by stub…)": what the stub is

- `41f0d47` adds a stand-in for Scryfall's `POST /cards/collection` (plus its CORS preflight) to the hermetic
  network fixture.
  - It answers from the same fixture JSONs as `/cards/named` and `/cards/<id>`.
  - It matches each identifier by id, name, or set + collector number. The rest go in `not_found`, which is
    Scryfall's real contract.
- **It does not hide a product bug.**
  - The seat metadata lookup (`useSeatCardMetadata` → `cardCatalog.lookupCards`) posts to `/cards/collection` at
    the original `5a8feae` too (`PlayerBox.tsx:1393`). This is existing, intended product behaviour.
  - The original's fixture answered every `api.scryfall.com` path with a single-card JSON or 404, including
    collection. The e2e-hardening fix in the base narrowed that to the card routes, so after the restack the
    request was aborted and `assertNoUnexpectedRequests()` failed the test. The test was failing on the network
    guard, not on behaviour.
  - The stub replaces a wrong-shaped answer with a correct one.
- Not a blocker. Minor M3 below asks for the "75/90" wording to be made exact.
