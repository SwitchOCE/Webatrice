# rv20 — review of R1 `claude/parity-r1-card-ops-seam` (tip 2f6e5b6, parent 17b 41f0d47)

Paths relative to `packages/webatrice/src/features/game/` unless noted. Every row was checked against the branch; desktop = Cockatrice `add65caa`.

**Brief questions, answered**
- *Characterization first?* Yes. 74fd4c9 adds only the spec. It passes 96/96 on the pre-refactor code and 96/96 on the tip. The spec covers all 46 seat ids (with a key-equality coverage check) and both arrow paths, and asserts exact `[method, params]` on `request.game.*`. Only 00445b5 changes it, and its two changed expectations are the two declared fixes.
- *Mutation test:* 16 single-field mutations. 15 are caught by at least one spec; the characterization spec alone catches 8. **Tap direction forced to `true` survives all 1497 game tests** (major below). Clone `y`, flip direction, attach/unattach judge wrap, drag `startZone`, counter bounds and the same-card zone check survive the characterization spec and are caught only by unit specs.
- *Exactly one implementation per card op?* Almost. Menu ops and all 46 shortcut ids send the same port calls, arguments, guards and order as before, with one undeclared exception (attach shortcut, below). The battlefield background menu keeps a fourth copy of increment-all-counters. Stack A (`useCardContextMenu`, `hooks/dialogs/useCardDialogActions`) still sends `bulk*` itself; that is acceptable because PR 30 owns it.
- *Lint rule:* the scope (`components/**`, `hooks/**`) and the override that repeats the WebClient rule are correct. The exceptions are wider than needed (rows below).
- *One pending owner, `usePendingArrows` gone?* Yes. `usePendingTarget` has one production instance and `createRequiredContext` throws without a provider. Judge wrapping (attach/unattach only) and arrow colour live only in `PlayerTargetCommands` / `arrowResolution`. Arrows are never wrapped, matching `CardItem::drawArrow`.
- *Stack A dead behind `GameInteractionContext`?* Yes. `useGameInteraction` has zero callers. `<CardContextMenu/>` is mounted but opens only through `handleCardContextMenu`, which is reachable only through that context. It is kept and moved onto the ports, as the PR says. `handlePlayerClick` is dead too but isn't stack A (nit below).
