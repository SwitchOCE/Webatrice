**Checked and OK**
- **Settings defaults and readers.** All 27 new keys match libcockatrice_settings defaults. The counter colours equal `fromHsv(id*60,150,255)`, and the spin ranges match. Every key has a non-test reader, so no option is a no-op.
- **Click-to-play.** The routing matches `PlayerActions::playCard`: stack spell → graveyard, Shift → face down onto tablerow 2, playToStack honoured. A battlefield click toggles the selection as `TableZone::toggleTapped` does. Play-all-selected goes highest id first.
- **Arrows and layout.** The arrow lifetime matches `getSubPhasesEnd`+1. Multi-column switches at `n >= min`. The vertical hand is 1.5 cards wide.
- **Animation choice.** Enable/Disable all set exactly desktop's four toggles. Reduced motion is followed live through `useSyncExternalStore`, and Restore defaults resets `animationsChosen`.
- **Architecture.**
  - Settings go only through the registry and `usePreference`. The diff adds no localStorage and no parallel stores.
  - There are no feature→feature imports. Board behaviour sits in the seat hooks.
  - `replayGameTime` is optional, and the changesets name the right packages.
- **Tokens and i18n.**
  - Every new token is in both palettes, `tokens.css` and Tailwind, and the CSS↔TS drift test covers them.
  - The ring contrast assertions can fail and pass: light select 3.35, attach and untap 4.57; dark select 5.08.
  - `i18n-default.json` equals the merged files.
- **Performance.**
  - The PR adds no board-wide render cascade. `usePreference` is a per-key `useSyncExternalStore`, so a `SeatCard` subscription costs little.
  - The drag count is set in the same `setMarquee` update, so it adds no render.
  - `useApplyCardPresentation` writes CSS variables only on change.
  - One finding is pre-existing, outside this PR: each marquee `pointermove` calls `setSelection` with a new `Set` and no equality bail-out, which re-renders every seat. The new counts depend on that path. A same-members bail-out plus rAF throttling in `useSeatSelection.ts:84` would fix it (follow-up).
- **Limits.** Nobody ran a profiler. The perf findings are reasoned from the code. No tests were run.

**Verdict: ready after fixes.** The one major (animations that Disable all and reduced motion leave running) needs either gating or an honest UI text. The rest are minor parity and a11y fixes.
