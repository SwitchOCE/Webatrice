## What I verified (no finding)

- **Network behaviour is byte-identical.** I compared old `cardCatalog.ts` against the new `catalog/*` + `scryfall/client.ts` line by line, after sorting and with comments stripped. The only differences are renames: `CHUNK`→`SCRYFALL_COLLECTION_LIMIT`, `RETRY_CAP`→`SCRYFALL_NAMED_RETRY_CAP`, and the URL literals → builders.
  - The collection init stays `{method, headers, body}`, with `signal` only when passed.
  - The named GET still takes one argument.
  - Catalog chunks are still sent in parallel. Pricing and oracle text are still sequential.
  - The 50-name retry cap and its warn text are unchanged.
  - Printings use the same URL: `encodeURIComponent('is:gamechanger')` = `is%3Agamechanger`.
  - The oracle init is `{method, headers, body, signal}`, the same as the old spread form. Game Changers is still `{signal}`, and the detail fetch is still `{signal}`.
  - No throttle was added, so timing is unchanged.
- **The characterization came first and was not edited afterwards.** `5288a13` adds the request-shape specs against the old code. `65bcaa5` (the client move) leaves `cardCatalog.spec.ts` untouched. `2ec1745` renames it to `lookup.spec.ts` and changes only its import and mock paths. The cache-hit paths were already pinned before this PR: cached record → no fetch, a cache `bulkGet` hit skips the network, and the session memo excludes unknowns. So were the split-card front face, the retry cap and the printings URL.
- **Layering.** `services/scryfall` imports only `@cockatrice/datatrice` (the `ScryfallImageSize` enum) and its own files: no hooks, store or UI. The catalog split follows real seams: `dexieCardMapper` / `scryfallCache` / `scryfallCardMapper` / `lookup` / `types`.
- **Call sites.** The only non-spec `api.scryfall.com` / `cards.scryfall.io` / `svgs.scryfall.io` strings left are the client and image builders, `pictureUrlTemplates.ts` (desktop's picture-URL defaults), `scryfallImage.ts` (size rewriting), a comment in `PlayerInfoPanel.tsx`, and `decks/search.ts` (sanctioned). No ad-hoc Scryfall `fetch` remains outside `services/scryfall`. The nine D5 image sites all use the same size as before (large/png/normal/art_crop/small). The only change is `encodeURIComponent` on ids, which is the identity for UUIDs.
- **D7.** The moved component is the deck pair (default 14). The game callers that relied on the old default of 16 (`BattlefieldSidebar`, `CardPreviewPopupPage`) now pass `size={16}`. `BigCardPreview` (18) and `PlayerInfoPanel` ("2em") were already explicit. `getScryfallSymbolUrl` has the same logic as both old URL builders. Nothing visible changes.
- **D12.** `gridNavigation.ts` is `listKeyboard.ts` verbatim, apart from the `GRID_PAGE_ROWS` name. Manage Sets is unchanged. `useGridRows.spec` covers PageDown/PageUp, including the clamp at both ends. None of the seven `useGridRows` grids is virtualized, so a ten-row jump always lands on a rendered row.
- **Dexie.** No version bump. The only change in `v2.schema.ts` is a comment.
- **Sideboard plans.** Desktop `DeckList::write` writes metadata → zones → plans, and `readElement` reads `sideboard_plan` children. The web codec now does the same. Every save path (`deckPersistence`, `deckExport`, `deckImport` re-upload, `hydrate`) carries the plans, and the save signature includes them.
- **D13.** The pieces I checked are value-identical:
  - the glow string;
  - `formatLeaveMessage`: its text and segments are pinned by a spec, and it is not exported from the datatrice package;
  - `formatLocalDateTime`;
  - `deckColorIdentity`: the deleted `deckSharing` copy had no non-spec callers;
  - the changeset's grid list, which matches the seven `useGridRows` callers.
